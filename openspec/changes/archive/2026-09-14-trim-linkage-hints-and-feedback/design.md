## Context

当前界面同时承担能力说明、组合推荐和结算解释，导致招募与战前阶段直接给出武将联动答案，而结算阶段又没有量化马超随机追击实际带来的收益。规则内核已经在 `Score` 中保存保底值 `floor`、最终值 `total`、额外计分步骤和追击次数，因此这次只需重新划分信息出现的时机。

## Goals / Non-Goals

**Goals:**

- 出牌前保留单张武将能力，但移除组合建议，让玩家自行发现联动。
- 始终以确定结果作为保底预览。
- 在马超追击成功后准确显示相对保底值增加的攻势。
- 没有额外计分时明确使用“普通结算”。

**Non-Goals:**

- 不修改武将、牌型、数值、概率、随机顺序或存档结构。
- 不增加预计区间、新资源、新操作或教程步骤。
- 不移除结算后用于解释已发生结果的因果链和流水。

## Decisions

1. 招募、开局选择、商店和战前界面不再渲染 `hint` 组合建议，但继续显示武将的 `text` 能力正文。这样移除的是答案提示，而不是理解规则所需的信息。删除能力说明会让选择退化为盲选，因此不采用。
2. 试玩入口只说明它是独立试玩，不再指定一套武将触发顺序。试玩规则和固定阵容保持不变，避免把呈现调整扩大成内容调整。
3. 是否属于连锁结算由已有 `score.steps` 中是否存在 `额外计分牌` 判断。不存在时显示“普通结算”，并隐藏连锁等级；存在时保留“连锁结算”和事后因果链。
4. 马超成功收益在结算后按 `score.total - score.floor` 计算，并以“本次连锁令最终攻势增加 N”呈现。该差值包含本手所有成功追击的实际总收益，和玩家看到的保底预览可直接对应。预览阶段不显示范围或期望值。

## Risks / Trade-offs

- [移除组合建议后新玩家发现联动更慢] → 保留清晰的单将能力正文、保底预览和结算后因果解释。
- [一次多次追击只展示合计收益] → 使用“本次连锁”措辞，并让详细结算流水继续承担逐次解释。
- [旧 `hint` 数据仍存在于内容层] → 本次只停止玩家界面渲染，避免无关的数据迁移；后续确认无其他用途时再清理。

## Migration Plan

这是纯呈现变更，无存档迁移。更新共用前端并重新打包 macOS 与 Windows；回滚时恢复对应前端提交即可。
