## Context

当前规则内核在出牌后生成完整 `Score`，将征程状态暂存为 `settlement: pending`，再等待玩家选择 `bank` 或 `gamble`。这个暂停原本用于战后押分，但也承担了隐藏随机追击、逐步播放结算以及中途保存恢复的职责。删掉玩家选择时，仍需保留这些职责，避免提前泄露最终分数或破坏旧存档。

## Goals / Non-Goals

**Goals:**

- 取消战后押20%的风险选择和对应随机数消耗。
- 结算动画完成或被跳过时自动、全额、一次性入账。
- 保留随机追击揭晓、因果链、纪录、征募品质和旧存档恢复。
- 用单一结果条明确显示本手已经入账及本关剩余目标。

**Non-Goals:**

- 不修改马超能力、额外计分概率或最大追击次数。
- 不修改计分、Boss、关卡目标、征募概率或存档版本。
- 不用新的奖励或风险机制替代战后押分。

## Decisions

1. 保留内部 `pending → bank` 状态，但不再向玩家提供 `bank` 或 `gamble` 按钮。普通动画播放完、跳过动画、减少动态效果和恢复旧待结算存档时，客户端自动发送内部 `bank` 行动。这样最终随机结果仍按步骤揭晓，入账只发生一次。
2. 从公开行动联合类型和规则实现中移除 `gamble`，删除 `wagerValues` 和对 `rng.ai` 的消耗。`bank` 暂时作为内部结算行动保留，供自动结算和旧待结算状态使用。
3. 保留存档字段 `settlement` 及旧值 `win/loss` 的读取能力。新局只产生 `pending` 和 `bank`；旧的已押注结果按原分数继续游戏，旧的 `pending` 在进入结果页后自动全额入账。
4. 将战后面板缩成只读结果条，显示“本手入账”和剩余目标。下一步按钮只在动画及自动入账完成后出现。

## Risks / Trade-offs

- [自动结算发生在客户端动画边界] → 规则内核仍以幂等保护拒绝重复 `bank`，恢复待结算存档时立即自动完成。
- [保留旧 settlement 字段会留下内部历史命名] → 这是兼容成本，不再显示给玩家；未来存档大版本再统一迁移。
- [删除押分会降低一次随机点击] → 马超追击继续承担构筑内的随机爆发，结算节奏更集中。
