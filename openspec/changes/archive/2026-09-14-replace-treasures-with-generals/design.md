## Context

当前 22 个永久构筑内容共用五个槽位、征募流程和结算顺序，但其中 12 个是武将、10 个是军宝。两类内容在规则上没有差异，只增加了玩家需要记忆的名词。内容 ID 同时被存档、测试和策略脚本引用，因此人物化调整必须保持 ID 与数值稳定。

## Goals / Non-Goals

**Goals:**

- 让 22 个永久构筑内容全部以三国人物呈现。
- 将玩家可见的“组件”“军宝”统一为“将星”。
- 保留现有效果、价格、稀有度、随机流和 v8 存档兼容性。

**Non-Goals:**

- 不新增构筑系统、槽位或结算阶段。
- 不调整分数、概率、价格或稀有度分布。
- 不更换稳定 ID，不升级存档格式和内容版本。
- 本次不制作新的角色立绘。

## Decisions

### 保留稳定 ID，只替换人物身份

10 个军宝 ID 继续作为内部标识，分别映射为马超、陆逊、太史慈、张辽、公孙瓒、庞统、董卓、鲁肃、荀彧和孙策。这样旧存档恢复后会得到相同能力，自动策略与随机结果也不会变化。另一方案是创建新 ID 并迁移存档，但它会增加迁移代码且不能带来玩家价值。

### 效果改写为人物战法，数值与触发时机不变

装备意象不再充当独立牌名。每名新武将用简短战法文案解释原有效果，计分账本的来源名称随人物名更新。这样能加强人物记忆，同时保证调整前后的同一种子分数一致。

### 玩家界面统一称为“将星”

征募、商店、槽位、规则和内容文档统一使用“将星”。代码中的 `COMPANIONS`、`companions` 与既有类型名继续保留，避免无价值的大规模内部重命名。品质名称统一为良将、名将、传奇。

### 不提升内容版本

本次只改变展示身份，所有机械语义和序列化数据保持兼容。继续使用 v0.7 与 schema v8，确保现有存档可以直接载入。

## Risks / Trade-offs

- [人物与既有效果的联系不够直观] → 用战法名与一句结果明确的文案建立人物性格，不增加额外规则。
- [失去标志性装备的收集感] → 将装备意象留给后续美术和技能表现，本次先验证统一人物是否更易理解。
- [旧存档中相同 ID 的显示身份改变] → 机械效果完全保留，并用恢复测试验证不会丢失构筑。
- [文档与界面残留旧术语] → 全仓搜索旧名称与“军宝”词汇，并以浏览器流程截图复核。

## Migration Plan

更新内容配置与计分来源名称，再更新界面、规则和文档。运行单元测试、固定种子模拟和浏览器流程；确认分数基线不变后重新打包 macOS 与 Windows。若需要回滚，可整体回退本次提交，存档无需逆向迁移。

## Open Questions

无。人物映射、术语与兼容策略均在本次变更中确定。
