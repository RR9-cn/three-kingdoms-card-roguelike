## Context

现有 v0.1 桌面原型已验证流程。用户反馈缺乏吸引力，批准构筑为核心的 v0.2。旧验收记录仅覆盖旧版。

## Goals / Non-Goals

Goals：开局选核心；第三关前能形成方向；永久改牌提高一致性；结算能解释成长与连锁。Non-Goals：本轮不做正式商店、联网、无限循环、最终美术和真人平衡结论。

## Decisions

1. 纯 core 新增 forge 模块，复用牌型与独立 RNG，常驻效果白名单配置放 content。默认六张选三张；每关4次出牌、2次换牌，换牌可选1–3张。每关重洗本局牌库，战内抽牌不放回，空牌堆时仅洗弃牌。36 张起始牌，ID 唯一，牌面可重复。
2. 八关目标配置化；基础 chips 与 mult 由牌型和其本局等级决定。先结算单牌及重复触发，再按组件槽顺序执行加法和乘法，再向下取整累计攻势。成长组件本次先成长再生效，预览用克隆模拟，不提前写回。提供完整结算流水。
3. 20 组件5槽，三条交叉方向：对子成长/重复计分、同兵种/改牌、低点/经济。开局公开三选一（关羽、周瑜、刘备），后续奖励从未持有池独立采样；不暗中保送配件。升级牌型、删牌、复制、升点、强化和改兵种必须明确目标，验证后一次提交。局内成长随组件出售丢失，持有与效果均显示。
4. 征募免费三选一或拿钱 → 一次免费整编 → 固定货架商店，可付费刷新（每次涨价）、买卖和调整组件顺序 → 战前公布目标/限制，选择加压（目标×1.5、胜后额外8军资）→ 战斗。开局12军资；胜后10+剩余出牌次数+利息（每5军资1、上限5）。容量满时必须明确替换；钱不足/无效目标不改变任何状态。出售返还标价的一半。
5. schemaVersion2/contentVersion0.2.0，独立双槽。校验版本、牌ID和分区、组件及阶段；旧模式存档保持原样。序号拒绝重复命令，UI 决断后显式下一手防双击跨手。视图仅公开手牌、完整可编辑牌库和历史，不公开未来牌序/RNG。
6. 复用现有隔离 Electron 主进程，Vite 多页打包默认 v0.2 与 legacy.html。原生 macOS 与浏览器分开验证。Windows 包不代表原生验证。

## Risks / Trade-offs

- 组合过强/路线单一 → 记录不同开局组件的种子模拟，优先试玩，不声称平衡。
- 复杂结算难理解 → 选择时显示即时预览与来源，结算逐步点亮并可跳过动画。
- 换皮感 → 使用独立武将/改编语义与三张阵型，保留原创效果和公开敌军规则。
- 新旧证据混淆 → 新版测试、截图和存档明确 v0.2。

## Migration Plan

默认入口切到新模式；旧页面、核心、素材和历史文档保留。新模式不读取或覆盖旧存档。仅本地构建；发布、Windows 原生与五人试玩继续待办。

## Open Questions

实际关卡时长、构筑选择与挑战曲线由试玩确认；本轮先交付可玩的验证切片。

## v0.3 试玩反馈修订

基于一次从第4关开始的真人试玩：虎符倍率从1.8降到1.25，加压目标仍1.5，避免加压相对更轻松。第4关伏击：每手未换牌时攻势×0.65，本手换牌后解除；有限换牌需在各手之间分配。第7关变阵：首张出牌兵种与上一手相同时攻势×0.5，鼓励留牌和换兵种。既有第6关牌型变化与末关次数限制保留。不按玩家强度动态抬目标。规则公开且预览一致。

schemaVersion3/contentVersion0.3.0，新独立存档键保留v0.2进度；新字段scouted记录本手已换牌、lastSuit记录上手首牌兵种。先用同种子比较贪心出牌与公开信息换牌策略，不将模拟胜率等同真人乐趣。

第4关张宝、第8关张角各两阶段。累计攻势达到实际目标的40%（向上取整）后下一次出牌适用新规则，阶段由score/target推导，无新增可失配状态；跨界一手全程按出牌前阶段计算。伤害全额累计，可越过阶段直接击杀。剩余出牌和换牌不刷新。

张宝第一阶段伏击×0.65、换牌解除；第二阶段替换为连续同牌型×0.5。张角第一阶段正常计分，第二阶段雷劫：出牌移除所选三牌后、补牌前的剩余手牌有谋牌则正常，否则×0.6。可以选择承受惩罚，流派不被硬禁止。三次出牌限制保留。

首领称号、印章、兵力条、双阶段预告、变招与击败台词显示在战场，沿用代码视觉，不伪称新增角色立绘。schema3/content0.4.0，独立v4存档保留v3.1。

## v0.5 连锁、品质与自愿押分

以当前 GAME_DESIGN.md 为运行规则：确定保底 + 追击令35%有限追加 + 连营鼓；实际出牌提交随机结果并消耗手数，先待入账。bank/gamble一次性结算，再由next推进；next在pending时视为安全收兵，用于键盘/合法核心调用。分数、纪录、品质与Boss阶段均以已结算值为准。随机复用未使用的enemy/ai独立流，不影响player/reward。抽品质后抽个体，缺档归一化、无放回。胜利extend接奖励，depart递增challenge，失败保留基础通关。schema5/content0.5.0，独立v5存档，历史纪录独立展示。

演出只揭晓真实事件，不能先显示最终随机收益；预览不抽随机。上限1万亿保持数值稳定，不提供达到上限后只有下行风险的押分。

## v0.5.1 随机战后整编

战后整编不再要求玩家先选六类操作再遍历整副牌库。界面只提供一次“军师整编”：从复制随机阵牌、随机阵牌升点、随机阵牌强化、随机牌型升级四类正向结果中等概率抽一类，再随机合法目标；达到上限的类别临时移出池。删牌与改兵种不进入随机池，避免系统在没有玩家选择时破坏构筑。玩家仍可跳过并获得3军资。

结果使用 reward 随机流并写入状态，重复或阶段错误的命令不推进随机。整编完成后在商店展示具体结果，离开商店后清除提示。schema6/content0.5.1，独立v6存档保留v5。

## v0.5.2 张角像素演出样板

第八关张角加入 PixelLab 96×96 像素角色，以正面方向制作待机、受击、举杖引雷和败亡四组动画。界面根据公开状态选择动作：备战与普通选择显示待机；已出牌待入账显示受击；跨过40%阶段线显示引雷；击败显示败亡。阶段变招额外使用代码生成的雷光、暗场和屏幕震动，以素材动作作为主体。

动画属于渲染层，不改变 core 状态、随机、分数或存档版本。减少动态效果时停在各动作的可读关键帧。素材放入独立 `assets/bosses/zhang-jiao/`，记录 PixelLab 角色ID、提示词、动画组ID与实际帧数。
