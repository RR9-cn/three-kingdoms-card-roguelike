## Context

`simulate_batch`目前要求一个或多个固定开场贵宾，并把开场 ID 传给`forgeStrategy`选择整局购买顺序。因此不同开场的结果混合了规则强度与预设策略强度。正式游戏已经改为按现有稀有度权重随机展示一位开场贵宾，且自由构筑不应以固定名单定义流派。

## Goals / Non-Goals

**Goals:**

- 用与正式新局相同的确定性随机开场生成批量样本。
- 用一套不读取开场配方的策略完成所有对局。
- 根据实际出牌、触发和最终贵宾事后归纳构筑结构。
- 用有界 JSON 返回策展人依赖、第七场可达性、规则轴使用与常见胜局结构。

**Non-Goals:**

- 不修改贵宾效果、关卡目标、经济、牌库或正式游戏 AI。
- 不把统计分类显示给玩家，也不建立固定套装或流派标签。
- 不把自动策略胜率解释为真人胜率或付费意愿。

## Decisions

### 增加独立的开放生态操作

新增`simulate_open_ecology`，而不是改变`simulate_batch`默认语义。旧接口继续服务固定开场回归，新接口明确采用随机开场和统一策略，避免历史请求静默改变含义。

### 开场复用正式随机结果

每个种子调用`newForge(seed)`，接受其公开的单个`recruits[0]`并开始征程。这样复用正式稀有度权重和随机流，不在评测器维护第二份概率表。

### 购买依据公开目录的边际价值

统一策略不读取开场 ID 对应的购买顺序。对货架候选及可能的替换方案，使用当前公开目录产生的固定代表三件组合，比较加入候选前后的确定性预览收益；撤换现金等无法由单手预览覆盖的效果只使用简短、通用的公开资源估值。该估值只决定评测动作，不写入游戏规则。

候选抽样从公开目录按稳定索引取得，使用独立固定预览随机状态，不读取真实抽牌顺序或核心随机状态。购买必须具有正边际价值，并照常支付价格；目录调整和离场沿用相同的通用逻辑。

### 事后记录规则轴

每次上拍前从所选三件拍品与公开战斗状态记录：成对、低估值、同类别、年代序列、三类别、传世三件套、高估值和最后一轮。结算后记录是否实际发生追加竞价。规则轴描述发生过的选择，不规定贵宾组合。

每局以实际活跃手数达到门槛的规则轴形成`axisSignature`，再与最终贵宾 ID 集合分别聚合。响应仅返回出现次数最多的有限结构，并单独统计所有胜局中每位贵宾的出现率以及无策展人胜局。

## Risks / Trade-offs

- [边际预览低估经济与长期成长] → 单独返回策略说明，并把结果限定为回归证据；对撤换现金、精简目录和最后一轮采用通用资源估值。
- [事后签名可能把偶然牌型当成构筑] → 只有达到至少两手且占本局一定比例的规则轴进入签名，同时保留最终贵宾组合供交叉检查。
- [精确枚举目录组合运行成本高] → 使用由公开目录稳定生成的有界样本，确保运行数增加时响应和单局成本仍有上限。
- [新操作与旧批量结果混用] → 在`meta`中标明`adaptive-open`策略及解释边界，保留旧操作不变。
