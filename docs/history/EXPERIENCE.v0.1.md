# 体验、美术与验证计划

## 战斗屏幕

设计基准 1440×900，最低验证 1280×720。常用操作目标至少 44×44，正文目标 ≥14，关键点数 ≥24。键盘 1/2/3 选择己方牌，Enter 亮阵/下一轮，Esc 关闭菜单；按钮显示焦点样式。

桌面中部为战场与三张阵牌，左侧为主将、军宝和征程，右侧为情报、锦囊与最近战报。敌方三牌在战场上半，己方大牌在下半。底部固定换阵、侦察、亮阵、加压与撤阵，确认加压前解释双向风险。缩小窗口时侧栏自然换行，规则和点数保持可读。

`art-prototype/` 保留早期竖屏历史，不再代表目标平台。复用角色、配色和素材，新版阵牌展示点数与兵种，不复用旧技能牌规则。

## 首局教学：三个小问题

- 第一轮：明示演练模式，展示连阵胜合击，让玩家亮阵；结算逐项解释“牌型 → 战势 → 伤害”。
- 第二轮：给一张可换成对子的散阵，提示赵云免费换阵，允许尝试后亮阵；演练换牌结果固定。
- 第三轮起：切到正常随机，介绍敌方明牌和一次侦察；玩家可跳过提示。加压按钮首次展开解释“输了也更痛”；不强迫选择高战势。

教学前两轮要配置成不会杀死刀兵的伤害总和，并测试：第一轮可用战势 1 的低连阵打 8，第二轮对子打 7，20 兵力还剩 5。演练禁用加压、撤阵和锦囊，只开放该步教学动作；跳过整个教学则从新随机首战开始，不继承演练已造成伤害。

## 美术和声音

- 角色源图以 128×128 为首轮基准，图标 64×64；显示时使用 nearest 采样，统一像素密度。
- 兵种纹样与点数由引擎绘制，文字不烧进图片；颜色之外也用图标区分兵种。
- PixelLab 下一批首先做“枪骑弓谋”四枚一致图标、赵云/刀兵待机和受击，再做张角；现有长枪图可作枪兵种参考。
- 视觉主次：点数和牌型最重要，武将第二，场景第三；暂不铺大地图、剧情立绘和复杂粒子。
- 声音使用翻牌、换阵、战鼓加压、亮阵、受击五类反馈。默认可静音，后台暂停音频；无声音也能理解全部状态。
- 使用素材登记表记录服务、任务 ID、提示词、尺寸、版本和本地路径；先确认样板一致性再批量生成。

## 阶段验证

| 阶段 | 可审查交付 | 通过条件 |
|---|---|---|
| P0 规则 | 牌型内核、合法行动、回合重放 | 所有边界场景通过；同 seed + 行动得到相同结果 |
| P1 单战 | 赵云对刀兵浏览器灰盒 | 换阵、侦察、锦囊、加压、退让、平局、死亡均可演示 |
| P2 平台冒烟 | 同一核心接 Electron 桌面窗口 | 本机应用可启动；鼠键、重启恢复和文字渲染有记录 |
| P3 征程 | 八层路线、商店、军宝、Boss、存档 | 从开局走到胜利/失败；奖励不能双领；恢复不改变暗牌 |
| P4 美术与试玩 | 像素战斗、教学和试玩报告 | 5 位玩家中至少 4 位能解释加压代价，记录失败原因和节奏 |

P2 在 P1 后进行；分别记录浏览器、本机桌面和 Windows 原生证据。交叉构建不是 Windows 启动验证，本地 Demo 不是 Steam 上架。

## 必测边界

牌型全序与反对称、顺子边界 1-2-3 / 7-8-9 / 9-1-2、同点不同兵种平局、改牌后的重判、重复 ID 拒绝；零军令、重复侦察、超出换阵次数；同轮锦囊双用；Boss 战势 2；退让不触发亮阵军宝；护甲不挡撤阵和平局；第八轮消耗战；双方同时归零；奖励双击；存档迁移失败；观星中断；后台恢复和随机状态不变。

## 平衡实验而非结论

至少模拟 1,000 个征程种子，对照“立即亮阵”“只换阵”“总加压到 3”“按信息决策”四种策略。记录胜率、平均剩余兵力、战斗轮数、每类牌型胜率、军宝选择率和节点路径；不得只报单个胜率。

如果总加压策略持续压倒信息策略，先调整退让收益和风险系数；如果撤阵从不被选择，调整撤阵损失或公开信息；如果顺子流显著落后同花流，先调锦囊可达性。第一轮设计概率枚举只给自然发牌分布，不能替代这些策略实验。
