# AI本地评测接口验证 v1

评测器通过一个版本化JSON请求在本地完成全部游戏模拟，AI只读取聚合结果或指定种子的紧凑摘要。首版提供`simulate_batch`、`inspect_run`和`compare_rules`三个操作。

## 实际规模

- `simulate_batch`：关羽、周瑜、刘备各200局，共600局；耗时2.52秒，响应9,803字节。
- `compare_rules`：正式规则、刘备+5倍率、第二关260目标三个方案，各方案600局，共1,800局；耗时7.08秒，响应6,096字节。
- `inspect_run`：展开一个刘备高爆发代表种子，响应4,985字节，最多八条逐关摘要。

运行次数增加不会附加逐局日志。批量响应只保留逐关分位数、最多12条异常和每个开局3个代表种子；比较响应只保留胜率差和绝对变化最大的12项逐关指标。

## 本轮发现

固定`counterplay`策略下，刘备第1、2、3关一手通关率分别为69.5%、57%和50%，批量接口将三项全部标记为异常。代表高爆发种子`stage-balance-v1-174`在第3关由刘备、马超、周瑜形成连锁，单手1,596/320。

这些数值用于证明接口能定位问题，不构成最终平衡结论。自动策略不是人类玩家，也不衡量乐趣。

## 验证

- 54项核心与接口测试通过，包括确定性、默认规则一致性、隐藏信息隔离、参数校验、输出上限、文件CLI和配对比较。
- 10项浏览器回归测试通过，默认空参数没有改变玩家流程。
- OpenSpec严格校验通过。

证据文件：`ai-eval-stage-balance-v1.json`、`ai-eval-rule-comparison-v1.json`、`ai-eval-liubei-high-roll-v1.json`。
