# v0.5 连锁冲分与押分

本轮实现22组件、追击令35%有限追加与连营鼓、保底预览、品质加权招募、自愿20%押分、破本局纪录与本机历史纪录，以及八关后继续极限挑战。无位置战斗。

## 核心验证

64项规则测试、10项浏览器流程测试通过，包括：

- 预览不推进随机；追加最多3次且存在不触发和满追加路径。
- 押分只入账一次、失败可使原本致命的一手不足过关；之前分数与纪录不倒扣。
- pending和已押分状态恢复、重启不重抽、独立随机流不改变抽牌。
- 基础/中档/最高品质权重、空档归一化、3000次基础首抽分布、候选无重复及持久化。
- 极限挑战保留牌库、构筑、纪录和基础通关；失败不撤销八关成绩。

概率是公开设计参数，样本验证不是商业回报或真人胜率承诺。当前测试分布包含22组件中的武将和军宝。

## 浏览器与原生证据

完整流程使用公开操作、固定种子forge-2，覆盖胜利和失败。旧种子forge-0在新加权招募下不再保证当前策略通关，运行代码没有按种子保送内容。新增连锁、押分成功/失败、未入账、已入账恢复及极限界面专项使用明确的测试存档夹具。

截图burst-win-pending.png、burst-loss-settled.png、burst-endless.png为专项夹具。macOS打包程序完成八关、最小化暂停、重启恢复、极限挑战和已结算押分恢复；证据记录于forge-v05-desktop-smoke.json和burst-native-*.png。

## 模拟范围

forge-0.5.0-comparison.json记录1200局（3核心×200种子×2策略）。两策略使用相同招募偏好，不押分，分别不换牌／使用公开信息换牌。这只检查新分布下流程稳定与策略差别，没有评估押分最优性，也没有证明连锁带来重玩欲望。

## 待真人判断

是否愿意为破纪录、品质提升多换一次牌；35%追加是否能产生期待；20%押分的损失是否明确；极限挑战是否让成型构筑有发挥空间。美术为现有像素素材与代码排版，没有新增武将立绘。Windows原生与Steam发布未进行。
