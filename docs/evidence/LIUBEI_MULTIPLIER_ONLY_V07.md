# v0.7 刘备倍率单线验证

刘备从“每当不大于4点的牌计分，+10点数、+1倍率”改为“每当不大于4点的牌计分，+6倍率”。本轮只改变刘备的单次倍率幅度，未修改其他将星、牌型、关卡、追击、奖励或存档。

## 选择结构

刘备不再补偿低点牌缺少的基础点数。低点牌用于积累倍率，较高点数、强化和其他将星用于提供被倍率放大的点数，因此玩家需要在触发次数与基础点数之间取舍。额外计分仍会让低点牌再次触发刘备。

三种兵种的1、2、3组成连阵时：

- 累计点数：6。
- 连阵基础倍率：3。
- 刘备触发三次：+18倍率。
- 最终攻势：`6 × 21 = 126`，原版为216。

## 幅度校准

使用相同的200局公开信息贪心脚本比较倍率幅度；脚本不换牌、不加压，不代表真人胜率：

| 刘备每次触发 | 通关率 |
| --- | ---: |
| +1倍率 | 2.5% |
| +2倍率 | 7% |
| +3倍率 | 16.5% |
| +4倍率 | 24.5% |
| +5倍率 | 35.5% |
| +6倍率 | 45.5% |

最终采用+6倍率。正式三开局模拟结果为关羽88%、周瑜53%、刘备45.5%；刘备低于原版63.5%，但没有像+1倍率版本一样失去征程可行性。

## 验证结果

- 单元测试：45项通过，包括1、2、3固定示例和额外计分重复触发。
- 浏览器测试：10项通过，包括完整八关征程、Boss、存档和结算反馈。
- 生产构建、macOS arm64和Windows x64交叉打包通过。
- macOS arm64打包应用完成完整征程、极限挑战、暂停和重启恢复验证。
- OpenSpec严格验证通过。

Windows结果是交叉打包产物，仍不代表Windows原生运行验证。
