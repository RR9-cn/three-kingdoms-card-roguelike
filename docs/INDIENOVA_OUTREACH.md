# indienova 宣发与首轮真人测试计划

## 定位

indienova 是本项目在支付 Steam Direct 费用前的第一处公开入口。现阶段目标是找到懂独立游戏的种子玩家，验证陌生玩家能否独立理解并愿意再开一局；不以单篇阅读量、点赞数或短期销量判断游戏是否成立。

对外转化路径保持简单：

> indienova 开发日志 → 免费 Windows 测试包 → 五个问题的试玩反馈 → 下一篇公开复盘

测试包优先放在 itch.io 的隐藏或受限页面。itch.io 可免费创建项目并托管 Windows ZIP：[创建项目](https://itch.io/docs/creators/getting-started)、[费用说明](https://itch.io/docs/creators/faq)。未准备好公开搜索时不发布为公开新作。

## 第一个内容切口

首篇暂定题目：

> **从三国原型到午夜拍卖：为什么我只换题材，没有再加规则**

文章只讲“删减后如何留下一个能产生组合的核心”这一条线：

1. 最初用三国武将验证“三选一组牌 + 自由触发链”的卡牌肉鸽。
2. 早期版本能够算分，但布阵、军宝、赌博等尝试让选择越来越难解释。
3. 当前只保留六选三、组合热度、目录调整和贵宾自由竞价。
4. 用策展人从“两件同类别”改为“三件同类别爆发”的过程，说明如何在容易触发与值得构筑之间取舍。
5. 文末提供 Windows 免费测试入口，只询问玩家能否独立玩懂，以及结束后是否想换一种组合再开一局。

文章必须使用实际游戏画面。核心素材是一段 10～15 秒实录：三件同类别拍品上拍，策展人依次重拍三件，其他贵宾响应，成交价逐步上涨。不要用功能列表、未来承诺或与《小丑牌》的空泛比较代替实际过程。

## 三篇日志节奏

### 1. 设计删减

发布上述首篇文章，建立“只用三张牌产生自由组合”的项目记忆点。此时可以附少量截图，但测试包尚未通过 Windows 实机检查时不开放下载。

### 2. 免费测试开放

Windows 测试包可独立安装和完成八关后，发布第二篇短日志。写清版本边界、单局约需时间、系统要求、下载入口与反馈问题。首批只招募 6 人：

- 2 名玩过《小丑牌》《杀戮尖塔》等卡牌肉鸽的玩家；
- 2 名玩过卡牌游戏但不熟悉肉鸽的玩家；
- 2 名普通 PC 玩家。

优先邀请朋友的朋友和愿意交换试玩的独立开发者。测试时不口头讲解规则；前 3 人尽量共享屏幕或录屏，其余玩家异步完成。

### 3. 结果复盘

第三篇只公开反复出现的行为证据：玩家在哪里停顿、记住了什么组合、是否主动再开一局，以及项目据此只修改了哪一个问题。不要把 AI 批量策略胜率写成真人体验，也不要用一名玩家的最高分代替整体结论。

## 反馈问题

每名玩家结束后只回答五个问题：

1. 第一次看不懂发生在哪里？
2. 哪一手最有感觉，为什么？
3. 最后形成了什么贵宾或藏品组合？
4. 结束后是否想立即再开一局？想验证什么？
5. 如果当前版本售价为 20～30 元，会购买吗？不购买还缺什么？

观察记录与玩家原话分开保存。开发者不在试玩过程中解释正确答案，也不把礼貌性的“挺好玩”计为继续游玩的证据。

## 进入下一阶段的门槛

首批 6 人不是市场规模验证，只用于发现明显阻塞。满足以下条件后，再扩展到 10～20 人并考虑支付 Steam Direct 费用：

- 至少 5 人能在没有开发者指导的情况下完成前两关；
- 至少 2 人在第一次结束后主动开始第二局；
- 至少 4 人能说出自己构筑中一个真实发生的组合；
- 没有一个相同的理解或操作问题阻塞超过半数玩家。

如果未达到门槛，一次只修复一个重复问题，然后用新玩家复测。不要同时增加贵宾、场次、资源、长期成长和演出系统。
